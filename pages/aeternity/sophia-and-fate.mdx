# Sophia & FATE

**Sophia** is æternity's smart-contract language: functional, strongly and statically typed, with
contract-local mutable state. **FATE** (the Fast æternity Transaction Engine) is the virtual machine
that executes it. Every Superhero contract is written in Sophia and runs on FATE.

If you are arriving from Ethereum, most of your instincts transfer. The table covers the ones
that do not.

## Coming from Solidity

| Solidity | Sophia | Note |
| --- | --- | --- |
| `contract C` with a body in braces | `contract C =` with an indented body | Layout is significant, like Python or Haskell |
| `public` / `external` function | `entrypoint` | Only entrypoints are callable from outside |
| `internal` / `private` function | `function` | A local function, invisible off-chain |
| `view` / `pure` | a plain `entrypoint` | Closest syntax, but not a guarantee of global purity; see below |
| state-mutating function | `stateful entrypoint` | You must opt in; see below |
| `payable` | `payable entrypoint` | Contracts are non-payable by default |
| `msg.sender` | `Call.caller` | The calling entity, possibly another contract |
| `msg.value` | `Call.value` | Coins transferred in this call |
| `block.number` | `Chain.block_height` | Height of the block including this call |
| `block.timestamp` | `Chain.timestamp` | Unix time in **milliseconds**, not seconds |
| `emit Transfer(...)` | `Chain.event(Transfer(...))` | Events are a datatype, declared once as `event` |
| `mapping` | `map(k, v)` | A first-class value in Sophia, not a storage-only construct |
| `struct` | `record` | |
| `enum` | `datatype` | Sophia datatypes carry payloads, so they cover tagged unions too |
| `uint256` | `int` | Arbitrary precision on FATE, and signed |
| `address` | `address` | Same idea, `ak_`/`ct_` encoded off-chain |
| scattered storage variables | one `state` record, updated with `put` | There is no ambient mutable storage |
| `require(cond, "msg")` | `require(cond, "msg")` | Also `abort("msg")` |
| ABI | **ACI** | See below |

Three differences do real work:

**Contract-local mutable state.** A Sophia contract has exactly one `state` value. A stateful function
reads it and calls `put` with a new one; there is no assignment to a storage slot anywhere. This
is the language's state-update model. FATE separately rejects remote calls back into a contract
already executing on the call stack; that runtime check prevents reentrant contract calls.

**No floating point.** Sophia omits it. Every price, fee and curve value in Superhero is an
integer in aettos or token-decimals. See [AE & Gas](/aeternity/ae-and-gas).

**Types are checked, then checked again.** The compiler is strict, and FATE re-checks at runtime:
each FATE operation is typed, and a type mismatch is a runtime error: the call fails with return
type `error`, its state changes are discarded, and it is charged its full gas limit. A malformed
call does not corrupt state; it fails.

## Entrypoint annotations

Entrypoints are non-stateful and non-payable by default. The ACI records both flags:

| Annotation | Meaning | Omit it and… |
| --- | --- | --- |
| (none) | Cannot directly update this contract's state; normally called through a dry-run | This is the default |
| `stateful` | May update state, use stateful primitives, or call another contract with a non-zero value | The compiler rejects these operations |
| `payable` | May receive AE through this entrypoint | Calls with a non-zero value fail |

Emitting an event does not require `stateful`. A non-stateful entrypoint can also call a
stateful entrypoint in another contract with zero value. The flag alone does not prove that
an on-chain call has no effects.

`payable` also applies to the contract itself: a contract is non-payable unless declared
otherwise, so a plain AE transfer to a `ct_` address fails by default.

These map straight onto how you call a contract. A non-stateful entrypoint can be answered by a
dry-run without broadcasting a transaction, paying a network fee or prompting the wallet.
Dry-runs still execute under gas limits, and can also simulate stateful calls. Persisting a
call's effects requires a signed contract-call transaction. To attach AE to a payable call,
pass an `amount` option:

```js
// Calling a payable, stateful entrypoint
await factory.create_community(
  collectionId,
  tokenName,
  BigInt(initialBuyTokenDecimals),
  false,                              // is_private
  metaInfoMap,
  { amount: initialBuyPriceAetto },   // the coins this call carries, in aettos
);
```

## ACI: the ABI equivalent

**ACI** (æternity Contract Interface) is the JSON description of a contract's interface: its name,
its type definitions, its event datatype, and every function with argument names, argument types,
return type, and the `stateful` and `payable` flags. It is what a client needs to encode a call
and decode a result, the role Ethereum's ABI plays.

The ACI carries **named, typed arguments and the annotations**, so a client can tell a read from
a write without being told. From the Tipping v3 ACI:

```json
{
  "arguments": [
    { "name": "title",  "type": "string" },
    { "name": "media",  "type": { "list": ["string"] } },
    { "name": "author", "type": "address" },
    { "name": "sig",    "type": "signature" }
  ],
  "name": "post_without_tip_sig",
  "payable": false,
  "returns": "int",
  "stateful": true
}
```

You can read off that this is a write (`stateful: true`), that it takes no coins
(`payable: false`), and that `sig` is a first-class `signature` type. That is how delegated
posting passes an off-chain signature into the contract for `Crypto.verify_sig` to check.

### Generate an ACI

ACI is generated from Sophia source by the compiler:

```bash
aesophia_cli --create_json_aci Tipping.aes -o Tipping.aci.json
```

The same generation is available over HTTP from a compiler service at its `/aci` endpoint;
Superhero's web app uses the hosted compiler at `https://v7.compiler.aepps.com` for both
networks. Calling an already-deployed contract needs only its ACI, not a compiler. The agent
skill vendors the JSON files and reads them from disk:

```js
const ACI = JSON.parse(fs.readFileSync('./contracts/FungibleTokenFull.aci.json', 'utf8'));
await Contract.initialize({ aci: ACI, address: tokenAddress, onAccount: aeSdk, onNode: aeSdk.api });
```

Keep a vendored ACI in step with the deployed contract. A stale ACI can encode arguments or
decode results incorrectly, causing errors or misleading results.

The `@compiler >= N` pragma at the top of a `.aes` file is a minimum compiler version, not the
version the contract was built with.

## FATE, briefly

FATE runs directly on æternity's state tree rather than on a general byte-code machine bolted on
top of one.

- **Typed instructions.** Type errors fail the call rather than reinterpreting bytes.
- **A restricted memory model and high-level instructions.** æternity's FATE documentation
  reports that contracts tend to be smaller than their EVM equivalents.
- **Native access to chain features.** AENS names and oracles are reachable from contract code as
  protocol primitives, not through a precompile.
