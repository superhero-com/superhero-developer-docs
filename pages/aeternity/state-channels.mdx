# State Channels

State channels are æternity's layer-2 scaling mechanism: a two-party ledger whose agreed updates
usually happen off chain. Opening, closing and some other operations use on-chain transactions.
**Superhero does not use them.** Posts, tips, trades and votes are
individual on-chain transactions; chat runs on Nostr relays and video calls on Jitsi.

## How a channel works

**Opening** is an on-chain transaction. Both participants lock funds into the channel and agree on
an initial state, each authenticating it with a signature. From then on they exchange updates
directly with each other (a transfer, a contract call, any agreed change), each co-signed by
both parties and given a round number. None of it touches the chain, so none of it costs a fee
or waits for a block.

**Closing** is on chain again. In the happy path the participants co-sign a final state and
settle mutually. If one party disappears or misbehaves, the other can close unilaterally with
`channel_close_solo_tx`, publishing the state they claim is current. If a party publishes an
*old* state, the counterparty answers with `channel_slash_tx`, supplying a co-signed state with a
higher round number within the agreed `lock_period`. After that period, `channel_settle_tx`
pays out. Participants must retain the latest signed state and monitor the chain so they can
challenge an outdated closing state in time.

Opening and mutually closing a channel requires two on-chain transactions. Deposits,
withdrawals, disputes and forced progress can require more. The cost per update depends on
how many updates stay off chain and how often on-chain intervention is needed.

## Superhero and channels

Channels fit two-party, high-frequency interaction. A public social feed is neither: a post has
to be visible to everyone, and trading against a bonding curve is inherently many-party. The
closest thing in Superhero to "off chain" is [delegated posting](/social/delegated-posting),
where a user signs a message and a relayer pays for the transaction, but every post still lands on
chain individually.

If you need state channels on æternity, they are fully supported at the protocol and SDK level.
You would be building on the chain, not on Superhero.
