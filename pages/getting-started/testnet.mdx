# Using Testnet

æternity's public testnet (`ae_uat`) is where you experiment without spending real AE. Superhero has
a complete second deployment there, with its own backend, its own contracts, its own explorer.

## Network selection is a build-time decision

Superhero builds are **pinned to one network when they are built**, through the `VITE_NETWORK`
environment variable. It accepts `ae_mainnet` (the default) or `ae_uat`; anything else falls back
to mainnet.

The running app offers exactly one network, so switch your wallet to the same one from the wallet's
own settings. To use testnet, build for it:

```bash
VITE_NETWORK=ae_uat npm run dev
VITE_NETWORK=ae_uat npm run build
```

If you are also testing passkeys on that build, set the WebAuthn Relying Party ID to match your
origin, which passkey registration requires:

```bash
VITE_NETWORK=ae_uat VITE_WEBAUTHN_RP_ID=localhost npm run dev
```

See [Troubleshooting](/wallets/troubleshooting) if registration shows no prompt.

Testnet runs from your own build. The hosted wallet at `wallet.superhero.com` switches to testnet
from its own settings, which is enough to hold test AE, claim testnet `.chain` names, inspect AEX-9
balances and sign for a locally built app.

| Explorer | `https://aescan.io` | `https://testnet.aescan.io` |

| DEX backend | `https://dex-backend-mainnet.prd.service.aepps.com` | `https://dex-backend-testnet.prd.service.aepps.com` |

Network-independent settings, identical in both builds: the wallet endpoint
`https://wallet.superhero.com`, the Jitsi domain `meet.jit.si`, and the default Nostr chat relay
`wss://relay.superhero.chat`.

## Get test AE

Use the æternity faucet at **[faucet.aepps.com](https://faucet.aepps.com/)**: select Testnet, paste
your `ak_...` address, and submit. It also has a programmatic form:

```bash
curl -X POST https://faucet.aepps.com/account/ak_YOUR_ADDRESS
```

**The faucet has a per-address cooldown.** Request again too soon and it answers **HTTP 425** with
a message of the form "The address is graylisted for another …". Handle 425 explicitly in any
script that tops an account up: it is a wait, not a failure. Read the grant amount from the
faucet's response rather than hard-coding it.

Test AE is for testnet only. If you need more than one grant, wait out the cooldown and request
again, or run your own faucet from
[aeternity/aepp-faucet](https://github.com/aeternity/aepp-faucet), where the top-up amount is a
configuration value.

## Point a wallet at testnet

Superhero Wallet (extension, mobile app, or `wallet.superhero.com`) ships both networks in every
build. Switch under **Settings → Network**; custom networks can be added there too, with
per-protocol URLs.

Its æternity testnet defaults:

| Setting | Value |
| --- | --- |
| Node | `https://testnet.aeternity.io` |
| Middleware | `https://testnet.aeternity.io/mdw` |
| Explorer | `https://testnet.aescan.io` |
| Superhero API | Run your own from [superhero-api](https://github.com/superhero-com/superhero-api) |
| Tipping backend | `https://superhero-backend-testnet.prd.service.aepps.com` |
| Multisig backend | `https://ga-multisig-backend-testnet.prd.service.aepps.com` |

Once the wallet is on testnet it shows a **Faucet** entry (on the More screen and on the AE asset
screen) linking to `https://faucet.aepps.com?address=<your ak_ address>` with your address
prefilled. It is hidden on mainnet.

Because superhero.com is build-pinned, the two must agree: the network switch lives in the wallet,
so set the wallet to the network your build uses. See [Connecting a Wallet](/wallets/connecting).

## Point the agent skill at testnet

The agent-skill scripts target mainnet. `superhero-governance.mjs` reads `AE_NODE_URL` from the
environment and falls back to mainnet:

```bash
AE_NODE_URL=https://testnet.aeternity.io node scripts/superhero-governance.mjs ...
```

The other scripts set their node and API URLs as constants at the top of the file. To run them
against testnet, change those constants. Point the Superhero API base at your own instance, run
from [superhero-api](https://github.com/superhero-com/superhero-api) against the testnet node.

| Script | Constants to change |
| --- | --- |
| `superhero-wallet.mjs` | `https://mainnet.aeternity.io` |
| `superhero-post.mjs` | `https://mainnet.aeternity.io` |
| `superhero-comment.mjs` | `https://mainnet.aeternity.io`, `https://api.superhero.com` |
| `superhero-name.mjs` | `https://mainnet.aeternity.io`, `https://mainnet.aeternity.io/mdw/v3` |
| `superhero-invite.mjs` | `https://mainnet.aeternity.io` |
| `superhero-token-create.mjs` | `https://mainnet.aeternity.io`, `https://api.superhero.com` |
| `superhero-token-swap.mjs` | `https://mainnet.aeternity.io`, `https://api.superhero.com` |
| `superhero-read.mjs` | `https://mainnet.aeternity.io/mdw/v3` |
| `superhero-portfolio.mjs` | `https://api.superhero.com` |
| `superhero-trending.mjs` | `https://api.superhero.com` |
| `superhero-transactions.mjs` | `https://api.superhero.com` |

Until you have changed those constants, every agent-skill command is a **mainnet command spending
real AE**.
