# Community Tokens

A Superhero community token is an AEX-9 fungible token minted through bonding-curve buys and
redeemed through sells, with a DAO treasury attached. Holders can also burn their own tokens
directly without receiving AE. Creating one deploys a small cluster of
contracts in a single transaction; holding one gives you a governance stake and a write threshold in
that community, not a claim on a company.

| Property | Value |
| --- | --- |
| Standard | AEX-9 (æternity fungible token) |
| Decimals | 18, read from the token's `meta_info()` |
| Issuance | Minted on buy, burned on sell, via the bonding curve |
| Pricing | Exponential bonding curve, a pure function of supply |
| Buy/sell spread | 1% of the curve value: 0.5% to the community DAO, 0.5% to affiliation |
| Utility | Community governance voting, write-access threshold, community membership |
| Reserve design | Buys retain the immediate sell quote; full redemption follows in the continuous model, subject to integer-rounding analysis |
| Supply cap | None. Supply is elastic and grows with demand |

## What gets deployed

`CommunityFactory.create_community` deploys the whole community in one transaction, in a fixed
order:

| Step | Contract | Role |
| --- | --- | --- |
| 1 | `CommunityManagement` | Moderators, mute list, write threshold, community metadata |
| 2 | `DAO` | Owner and beneficiary of the sale; holds the treasury |
| 3 | `AffiliationBondingCurveTokenSale` | Buy, sell, mint, burn, affiliation fee routing |
| 4 | `FungibleTokenFull` | Created inside the sale's `init`: balances, transfers, allowances |
| 5 | None | Link the DAO, sale and management contracts |
| 6 | None | Optional initial token purchase, in the same transaction |
| 7 | None | Registration in the factory's on-chain community registry |

`create_community` returns the tuple `(DAO, TokenSale, CommunityManagement)`. The bonding curve
contract is shared: the factory exposes a single `bonding_curve()` and every sale contract points
at it, so all communities from one factory price on the same curve.

## Token address versus sale address

Both are `ct_` addresses and both appear on a token page.

| Address | Field on the API | What you do with it |
| --- | --- | --- |
| Token contract | `address` | AEX-9 operations: `balance`, `transfer`, `create_allowance` |
| Sale contract | `sale_address` | Everything about trading: `price`, `buy`, `sell`, `sell_return` |
| Bonding curve | `bonding_curve_address` | Read-only pricing maths |
| DAO | `dao_address` | Treasury, proposals, votes |

**The sale address is the handle.** Every CLI command, every portfolio row and every trending
listing keys off `sale_address`; you need the token address only for raw AEX-9 work such as
approving an allowance before a sell. The sale contract holds tokens under the account form of its
own address, so an allowance is granted to `sale_address` with its `ct_` prefix rewritten as
`ak_`. See [Buying & Selling](/tokens/buying-and-selling).

## What holding the token gets you

- **Governance.** Holders at or above the community's `minimum_token_threshold` can open DAO votes; any holder can vote, with voting weight equal to the tokens they lock in the vote contract. Opening a vote costs 555 AE, paid to the DAO. See [DAO voting](/dao/voting).
- **A treasury you collectively control.** Approximately 0.5% of the curve value on each buy is allocated to the community's DAO, and holders vote on how it is spent. Sells make no new DAO allocation. See [Treasury](/dao/treasury).
- **Write access and membership.** `CommunityManagement` stores a `minimum_token_threshold` that gates write access in the community for verified accounts, plus the moderator set and mute list. See [Moderators](/dao/moderators).
- **ProtocolDAO tokens.** Buying a community token also mints you platform-wide ProtocolDAO tokens, proportional to the AE value of the buy. Their governance framework is not yet live. See [ProtocolDAO](/dao/protocol-dao).

## What it is not

- **Not equity.** A community token conveys no ownership of any company, no share of profits, and no claim on anyone's assets other than the AE in its own bonding-curve reserve.
- **Not a revenue share.** The DAO treasury is spent by vote, not distributed automatically. There is no dividend.
- **Not a fixed-supply asset.** Anyone can mint more at any time by buying. Your percentage of the supply falls whenever someone else buys, even if your balance does not change.
- **Not backed by a promise.** The curve computes a sell quote from supply, and buys fund the reserve. The continuous-model redemption argument needs a separate check for integer rounding. Whether the quote is higher or lower than what you paid depends on what everyone else does. See [Reserve accounting and rounding](/concepts/value-flow#reserve-accounting-and-rounding).
- **Not free to enter and exit.** Before gas and integer rounding, an instant round trip with no intervening trades returns `0.995 / 1.005`, about `0.99004975` of what you paid. See [Risks](/tokens/risks).

## Two token types on the platform

| Aspect | Community token | ProtocolDAO token |
| --- | --- | --- |
| Standard | AEX-9 | AEX-9 |
| Scope | One community | The whole platform |
| Issuance | Minted on buy against the curve | Minted as a reward on every community-token buy |
| Price | Bonding curve | Not sold; issued only as a by-product of buying |
| Utility today | Voting, write threshold, membership | None yet. Issuance is live; governance is in development |

Every community-token buy mints ProtocolDAO tokens to the buyer at **1,000×** the AE paid,
affiliation fee included, after any surplus refund. The `Mint` event on the ProtocolDAO token
contract carries the exact figure. See [The ProtocolDAO Token](/dao/protocol-dao).
