# Superhero Wallet: Mobile

On a phone there are three ways to hold an account for Superhero: the Superhero app's built-in
wallet, the standalone Superhero Wallet app, and Superhero installed as a PWA.

## Two different apps

| App | Stores | What it is |
| --- | --- | --- |
| **Superhero — Web3 Communities** | [App Store](https://apps.apple.com/us/app/superhero-web3-communities/id6758045846) · [Google Play](https://play.google.com/store/apps/details?id=com.superhero.apps) | The Superhero social app, **with a wallet built in** |
| **Superhero Wallet** | [App Store](https://apps.apple.com/us/app/superhero-wallet/id1502786641) · [Google Play](https://play.google.com/store/apps/details?id=com.superhero.cordova) | The standalone multi-chain wallet, which signs for other æpps too |

To use Superhero, install the first. If you already have an æternity account elsewhere, or you want
one wallet across several chains, install the second and connect it.

## Install Superhero as a PWA

Superhero is also installable straight from the browser. The installed app gets a home-screen icon,
a full-screen experience, an integrated wallet and push notifications.

### iOS

**Use Safari.** It is the browser that installs PWAs on iOS.

1. Open [superhero.com](https://superhero.com) in Safari.
2. Open the page menu: the **⋯** menu in the top right, or the **Share** button on older iOS
   versions.
3. Scroll and tap **Add to Home Screen**.
4. Tap **Add** in the top right. The icon appears on your home screen.
5. **Launch it from the home-screen icon.** The installed capabilities are available in standalone
   mode.

### Android

1. Open [superhero.com](https://superhero.com) in Chrome.
2. Tap the **⋮** menu in the top right.
3. Tap **Add to Home screen** or **Install app**.
4. Confirm with **Install**.
5. Launch from the home screen.

On desktop, the same install is available from the install button in your browser's address bar.

## What changes once it is installed

| Behaviour | Browser tab | Installed app |
| --- | --- | --- |
| Create a built-in wallet (passkey or new phrase) | Yes | Yes |
| **Import** an existing seed phrase or private key | Use Connect | **Yes** |
| In-page signing by the built-in wallet | Signing goes through the connected wallet | **Yes** |
| Token community chat entry points | Hidden | **Shown** |
| Location sharing on iOS | Not available | Available |
| Push notifications | No | Yes |

In a browser tab the answer to "I already have a wallet" is Connect, which hands signing to the
extension or the wallet app through a redirect and never asks for your secret. The installed app
holds the key itself, so signing stays inside the app.

## The built-in wallet on mobile

Tapping **Connect** in the installed app offers a passkey option first. On a phone that means Face
ID, Touch ID, a fingerprint or your device PIN, and it creates a real æternity account in one
ceremony. The seed is *derived* from the passkey, so there is nothing to write down at creation.

**The passkey is your backup when it syncs** (iCloud Keychain, Google Password Manager), and it is
the copy of the seed for this wallet, so confirm that it does. Enroll the recovery code the flow
offers you, and read [The Built-In Wallet](/wallets/built-in-wallet) for what each factor restores.

## Push notifications

Push is standard Web Push (VAPID), opt-in, and enabled from a control in the app. The permission
prompt requires a tap, so it never appears on load.

- **Exactly one permission is requested**: the browser's notification permission. No location, no
  contacts, no background-refresh grant. Subscriptions are `userVisibleOnly`, so the browser will
  not deliver a push that does not show a notification.
- **Push needs a VAPID key on the server.** If the server has none configured, the app reports
  "Browser push is not configured on the server (no VAPID key)" and stops before prompting; if you
  run your own instance, configure a VAPID key to enable push.
- If the server's VAPID key is rotated, the app detects the change and re-subscribes for you.

## The standalone Superhero Wallet apps vs the installed web wallet

Installing `wallet.superhero.com` to your home screen is **not** the same as installing the
Superhero Wallet app. An installed PWA runs the web build:

| | Installed PWA of the web wallet | Native app |
| --- | --- | --- |
| Where the seed lives | Site `localStorage`, encrypted under your password | OS keychain, accessible when unlocked, encrypted with a per-install key |
| Unlock | Password (or none, if you turned protection off) | Biometrics (Face ID, Touch ID, fingerprint) or the device credential |
| Default auto-lock | 5 minutes of inactivity | **Immediately** |
| In-app dæpp browser | No | **Yes** |
| QR scanning | Browser camera | Native scanner |
| Ledger over WebUSB | Yes, on Chromium | No |
| AirGap pairing | Yes | Yes |
| Deep links | `https://wallet.superhero.com/...` | Also the `superhero://` scheme, and universal links on `wallet.superhero.com` |
| Kept when site data is cleared | Restore from the seed phrase | Yes |

**The native app is the place to hold value on a phone** (keychain storage and biometrics), and
the PWA is the convenient one. Back up the seed phrase in both cases.

## Connecting the standalone Superhero Wallet app

On a mobile browser the app connects over a deep link. Pressing
Connect tries the `superhero://` scheme first; if the native app does not take over within about
1.5 seconds, it falls back to opening `wallet.superhero.com`. The wallet signs and returns to the
app through the transaction queue route, described in [Connecting a Wallet](/wallets/connecting).
