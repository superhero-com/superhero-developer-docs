# Leaderboards

Superhero has one leaderboard: the **Trading Leaderboard** at
`https://superhero.com/trends/leaderboard`. It ranks wallets by on-chain trading performance
over a window you choose.

It covers trading performance. Affiliate earnings and rewards-program payouts are tracked on
`/trends/invite`; see [Rewards & Affiliation](/rewards).

## Metrics

Pick one metric at a time from the **Sort by** control. It maps directly to the `sortBy`
query parameter.

| Metric | Parameter | What it measures | Sort direction |
| --- | --- | --- | --- |
| PnL | `pnl` | Profit and loss over the window, in USD | Descending: highest first |
| ROI | `roi` | Return on invested capital over the window, as a percentage | Descending |
| AUM | `aum` | Assets under management: current portfolio value, in USD | Descending |
| MDD | `mdd` | Maximum drawdown over the window, as a percentage | **Ascending**: smallest drawdown first |

MDD is the one inversion: a small maximum drawdown is a good result, so the app sends
`sortDir=ASC` for that metric and `DESC` for the other three. If you call the endpoint
directly, do the same.

ROI is computed differently for the fixed windows and for **All**:

```text
7d and 30d
  pnl_usd = AUM at the end of the window − AUM at the start
  roi_pct = pnl_usd / AUM at the start × 100          (0 if the start AUM is 0)

all
  pnl_usd = total all-time gain, in USD
  roi_pct = total all-time gain / total all-time cost basis × 100
            falling back to the same ratio in AE if the USD cost basis is 0,
            and to 0 if both are
```

The 7d and 30d boards measure portfolio *growth*, which includes deposits and withdrawals made
during the window. The All board measures return on invested capital. A wallet can rank
differently on each.

For the All window, the window-based figures (the sparkline, the maximum drawdown, and the
buy and sell counts) cover **the last 365 days**. PnL and ROI are all-time.

## Timeframes

| Control | Sent as | Sparkline points |
| --- | --- | --- |
| 7D | `window=7d` | `points=7` |
| 30D | `window=30d` | `points=30` |
| All | `window=all` | `points=30` |
| Custom range | `startDate` and `endDate`, ISO-8601 | Not sent |

Custom ranges are entered as `dd/mm/yyyy hh:mm` in local time and converted to ISO-8601
before the request. Enter both ends, with the start before the end. When a custom range is
applied, `window` and `points` are omitted.

## What each row shows

| Field | Shown as |
| --- | --- |
| `address`, `chain_name` | The wallet, with its `.chain` name if it has one |
| `pnl_usd` | PnL for the timeframe, in USD |
| `roi_pct` | ROI for the timeframe |
| `aum_usd` | AUM, labelled "Latest portfolio value" |
| `mdd_pct` | Maximum drawdown for the timeframe |
| `buy_count`, `sell_count` | Buys and sells |
| `created_tokens_count` | Tokens this account created |
| `owned_trends_count` | Owned trends |
| `portfolio_value_usd_sparkline` | The inline sparkline, an array of point pairs |
| `volume_usd` | In the response, for API consumers |

Rank is computed client-side from the page offset (`(page − 1) × 15 + index + 1`), so it is
the rank within the currently selected metric and window.

For a custom range, `volume_usd` is populated and `created_tokens_count` and
`owned_trends_count` read zero; for the fixed windows it is the other way round.

## Who appears

**The board ranks the top 100 addresses by all-time USD traded volume**, ordered by whichever
metric you chose. Volume is the qualifier for every metric: build lifetime trading volume to
enter the pool, then the metric decides your place.

A second filter applies on read: `minAumUsd` defaults to **1**, so the board shows rows with an
AUM of at least one US dollar. Pass `minAumUsd=0` to include every row.

Custom ranges bypass the snapshot and compute live. The candidate pool is then the top
addresses by USD volume of buy and sell transactions **inside that range** rather than
all-time, sized by `maxCandidates`, default 100, maximum 500.

## Which trades count

Bonding-curve trades: `buy`, `sell` and `create_community` calls on community token sales,
both for the volume ranking that decides who is a candidate and for the `buy_count` and
`sell_count` on each card. [DEX swaps](/defi/swap), liquidity provision and plain AE transfers
sit outside this scope. Portfolio value reflects everything the account holds, so AUM and the
sparkline also move with holdings that the buy and sell counts do not cover.

`tradingOnly=true` narrows it further, for custom ranges only: it switches the
selected-period PnL and ROI to realised token-trading PnL and cost basis, excluding portfolio
value changes caused by transfers.

## The endpoint

```text
GET /api/accounts/leaderboard
```

Base URL is Superhero's API: `https://api.superhero.com` on mainnet.

| Parameter | Values |
| --- | --- |
| `sortBy` | `pnl`, `roi`, `aum`, `mdd`. Default `pnl`. |
| `sortDir` | `ASC` or `DESC`. Defaults to `DESC`, except `sortBy=mdd` which defaults to `ASC`. |
| `window` | `7d`, `30d`, `all`. Default `7d`. |
| `points` | Number of sparkline points. For `window` requests the snapshot sets it: 8 for 7d, 12 for 30d and 24 for all. For a custom range it is clamped to 2–12, default 8. |
| `startDate`, `endDate` | ISO-8601, both required together, end after start. Switches to the live path; use instead of `window`. |
| `minAumUsd` | Integer, 0 or more. **Defaults to 1**, so rows need an AUM of at least one US dollar. |
| `tradingOnly` | Boolean. Custom ranges only: bases PnL and ROI on realised trading PnL rather than portfolio value change. |
| `page` | 1-based. Default 1. |
| `limit` | Page size, 1–50. Server default 18; the UI sends 15. |
| `maxCandidates` | Custom ranges only: sizes the live candidate pool, default 100, maximum 500. |

The response is the standard paginated envelope: an `items` array of the fields above, plus a
`meta` object carrying `page`, `limit`, `totalItems`, `totalPages`, `window`, `sortBy`,
`sortDir` and a `timeFilter` block with the resolved `value`, `unit`, `start` and `end`.

```bash
curl "https://api.superhero.com/api/accounts/leaderboard?sortBy=pnl&sortDir=DESC&window=7d&points=7&page=1&limit=15"
```

The inverted case for drawdown:

```bash
curl "https://api.superhero.com/api/accounts/leaderboard?sortBy=mdd&sortDir=ASC&window=30d&points=30&page=1&limit=15"
```

## Freshness

**Server side**, the three `window` boards (7d, 30d and all) are recomputed from a snapshot
**every 10 minutes**, against a single reference timestamp per run, so every `window` request
reflects the chain as of the latest snapshot. Custom ranges compute live on the request, so
they take longer to return.

**Client side**, the app caches each metric-and-window combination for **60 seconds** and
keeps fetched windows in memory for **5 minutes**; switching metrics or pages within those
windows is served from cache.

## How to climb it

- Trade trend tokens regularly to build up volume. The top 100 by lifetime USD volume is the
  entry condition for every metric.
- Keep PnL and ROI positive over time.
- Own and hold trending tokens to grow AUM.
